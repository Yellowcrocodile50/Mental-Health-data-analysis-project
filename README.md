# Mental Health Care 데이터 분석

**MATRIX 미니프로젝트 · 6조 팀 프로젝트**

정신건강 관련 데이터를 전처리·가공해 **행복도(Happiness)를 예측하는 분류 모델**을 만들고 해석했습니다.

이 저장소는 결과 코드보다 **「왜 이렇게 결정했는가」의 기록**에 가깝습니다.
노트북 69개 셀 중 48개가 설명 셀이고, 데이터셋 선정부터 모델 선택까지 검토 과정을 지우지 않고 남겼습니다.

---

## 1. 데이터셋 선정 — 3개를 비교하고 골랐습니다

주어진 데이터로 바로 시작하지 않고 후보 3개를 놓고 비교했습니다.

| 후보 | 검토 결과 |
|---|---|
| Credit Card Fraud | 클래스 분포가 극단적으로 불균형 |
| **Mental Health** | ✅ **최종 선정** |
| AI Job Market | 분석 목적과 거리가 있음 |

각 데이터셋의 분포와 특성을 확인한 뒤 비교 요약표를 만들어 결론을 냈고, **왜 나머지 둘을 뺐는지**도 함께 적었습니다.

## 2. 모델 선정 — 같은 데이터, 네 가지 전처리

**조원들이 나눠 맡은 것은 모델이 아니라 전처리입니다.**
데이터셋과 타겟(`Happiness`), 알고리즘(Logistic Regression)을 **고정**하고
**전처리 방식만 4가지로 달리해** 만든 모델을 나란히 비교했습니다.

| | 전처리 방식 |
|---|---|
| 모델 1 | 전처리 없이 단순 오버샘플링 |
| **모델 2** | **모든 범주를 이진 분류로 변환** ← 제가 맡은 부분 |
| 모델 3 | 다범주 구간화 (많음 / 보통 / 적음) |
| 모델 4 | 분위수 기반 구간화 |

바꾸는 변수를 전처리 하나로 묶었기 때문에, **성능 차이의 원인을 전처리로 좁혀서** 볼 수 있었습니다.

### 제가 맡은 부분 — 모델 2

- **분석 파이프라인 설계** — 아래 3번의 Step 1~4 흐름
- **「모든 범주를 이진 분류로 변환」 전처리 설계·구현**
- **그 방식의 한계를 직접 정리** — 정보 손실 · 임계값 기준의 임의성 ·
  해석 깊이 저하 · 인사이트 도출 제한

장점(모델 단순화, 해석 용이)만 적지 않고 **단점 4가지를 같은 분량으로 남겼습니다.**
네 방식을 나란히 놓고 고르는 구조라, 내 방식의 약점이 적혀 있어야 비교가 성립한다고 봤습니다.

**최종 모델 선택과 회귀계수 해석·결론은 조원 전체가 함께** 진행했습니다.

## 3. 최종 파이프라인

```
Step 1  데이터셋 준비    불러오기 · 속성 확인
Step 2  데이터셋 분석    결측치 / 이상치 / 틀린값 확인 → 결측치 처리
                       → Happiness와 다른 컬럼의 상관관계 분석
                       → 피처 엔지니어링 & 인코딩 → 정규화
Step 3  모델 만들기      모델 생성 → 예측 및 평가
Step 4  모델 튜닝하기    과적합 진단 → 로지스틱 회귀 계수 분석
```

### 결과

| 지표 | 값 |
|---|---|
| Accuracy | 0.85 |
| **F1 Score** | **0.9020** |
| ROC-AUC | 0.9052 |

정확도(0.85)보다 F1(0.90)이 높게 나온 이유를 클래스 분포와 함께 확인했고,
**로지스틱 회귀 계수를 뜯어 어떤 변수가 행복도 예측에 얼마나 기여하는지**까지 해석했습니다.

정확도 하나만 보고 판단하지 않으려 한 것이 이 프로젝트에서 신경 쓴 부분입니다.
